# 🛍️ فروشگاه آنلاین پوشاک ایرانی (دمو)

یک فروشگاه اینترنتی کامل و راست‌چین برای مغازه پوشاک، کیف و کفش، ساخته‌شده با
**Django + HTML + Tailwind CSS + JavaScript**.

> فایل `README.md` در ریشه مخزن، معرفی پروفایل گیت‌هاب است و دست‌نخورده باقی مانده؛
> مستندات این پروژه در همین فایل قرار دارد.

---

## ✨ امکانات پیاده‌سازی‌شده

| امکان درخواستی | وضعیت | محل پیاده‌سازی |
|---|---|---|
| بنرهای زیبا زیر هدر با اسکرول خودکار | ✅ | `apps/core/models.py` (مدل `Banner`)، `templates/core/home.html`، `static/js/app.js` |
| صفحه پروفایل کاربری با شماره تلفن | ✅ | `apps/accounts/` (مدل `User` با `USERNAME_FIELD = phone`)، `templates/accounts/profile.html` |
| ویرایش نام کاربری (شماره) پس از تایید پنل پیامکی | ✅ | `apps/accounts/views.py` → `change_phone_view` / `verify_phone_view`، `apps/accounts/sms.py` |
| افزودن لوکیشن مغازه روی نقشه | ✅ | `SiteSetting` (مختصات یا لینک نقشه)، `templates/core/contact.html` |
| لینک تلگرام، اینستاگرام، واتساپ، توییتر و تلفن در فوتر | ✅ | `SiteSetting`، `templates/base.html` |
| کیف / لباس / کفش با سایزبندی و رنگ‌بندی متفاوت | ✅ | `ProductKind`، `Size`، `Color`، `ProductVariant` |
| چند عکس برای هر محصول + اسلایدر خودکار | ✅ | `ProductImage`، `templates/catalog/product_detail.html` |
| جداسازی دسته‌بندی زنانه و مردانه + انتخاب هنگام ثبت محصول | ✅ | `Gender`، `Category.gender`، صفحات `/shop/women/` و `/shop/men/` |

| مقدمات درگاه پرداخت | ✅ | `apps/payments/gateways.py` (درگاه آزمایشی + زرین‌پال) |

امکانات تکمیلی: سبد خرید مهمان و کاربر (با ادغام پس از ورود)، فیلتر و جستجوی
پیشرفته محصولات، مدیریت موجودی در سطح سایز/رنگ، کد پیگیری سفارش، و ۴۹ تست خودکار.

## 🚀 راه‌اندازی

```bash
# ۱) نصب وابستگی‌های پایتون
pip install -r requirements.txt

# ۲) ساخت دیتابیس
python manage.py migrate

# ۳) داده نمونه (بنر، دسته‌بندی، برند، سایز، رنگ و ۱۲ محصول)
python manage.py seed_demo

# ۴) ساخت کاربر مدیر (نام کاربری = شماره موبایل)
python manage.py createsuperuser

# ۵) اجرای سایت
python manage.py runserver
```

آدرس سایت: <http://127.0.0.1:8000> — پنل مدیریت: <http://127.0.0.1:8000/admin>

### کامپایل مجدد Tailwind (فقط هنگام تغییر قالب‌ها)

فایل `static/css/app.css` از قبل ساخته شده، پس برای اجرای پروژه نیازی به Node نیست.
اگر کلاس تازه‌ای به قالب‌ها اضافه کردید:

```bash
npm install
npm run build:css     # یا npm run watch:css هنگام توسعه
```

## ⚙️ تنظیمات محیطی

فایل `.env.example` را به `.env` کپی کرده و مقادیر را تنظیم کنید.

### پنل پیامکی

| متغیر | توضیح |
|---|---|
| `SMS_BACKEND` | `console` (نمایش کد در ترمینال و روی صفحه، حالت دمو) یا `kavenegar` |
| `SMS_API_KEY` | کلید API پنل پیامکی |
| `SMS_SENDER` | شماره فرستنده |

برای اتصال پنل پیامکی دیگر (ملی‌پیامک، فراز اس‌ام‌اس و…) کافی است کلاسی مانند
`KavenegarSMSBackend` در `apps/accounts/sms.py` بنویسید و آن را به دیکشنری `BACKENDS`
اضافه کنید.

### درگاه پرداخت

| متغیر | توضیح |
|---|---|
| `PAYMENT_GATEWAY` | `dummy` (درگاه شبیه‌سازی‌شده داخلی) یا `zarinpal` |
| `ZARINPAL_MERCHANT_ID` | شناسه پذیرنده |
| `ZARINPAL_SANDBOX` | `True` برای محیط تست زرین‌پال |

مبالغ در سایت به **تومان** است و هنگام ارسال به زرین‌پال به‌صورت خودکار در ۱۰ ضرب
می‌شود (ریال). برای افزودن درگاه جدید، کلاسی از `BaseGateway` با دو متد `start` و
`verify` بسازید و در `GATEWAYS` ثبت کنید.


## 🛠️ کار با پنل مدیریت

1. **تنظیمات سایت**: نام فروشگاه، لوگو، آدرس و مختصات مغازه، ساعات کاری، لینک شبکه‌های
   اجتماعی و هزینه ارسال. (لوکیشن: اگر لینک iframe نقشه را خالی بگذارید، نقشه از روی
   عرض و طول جغرافیایی ساخته می‌شود.)
2. **بنرها**: تصویر، عنوان، زیرعنوان، لینک و ترتیب نمایش در اسلایدر.
3. **دسته‌بندی‌ها**: هر دسته یک جنسیت (زنانه/مردانه/مشترک) دارد و همین باعث جداسازی
   کامل دو بخش می‌شود.
4. **برندها**: پس از افزودن، در فرم ثبت محصول قابل انتخاب‌اند.
5. **سایزها**: برای هر نوع کالا جدول سایز جداگانه است (لباس: `S/M/L`، کفش: `۳۷…۴۴`،
   کیف: کوچک/متوسط/بزرگ).
6. **محصول**: پس از انتخاب دسته، برند و نوع کالا، در همان صفحه چند **تصویر** و چند
   **تنوع (سایز + رنگ + موجودی)** اضافه کنید. جنسیت محصول خودکار از دسته گرفته می‌شود.

## 🔐 پیش از انتشار روی سرور

- `DJANGO_SECRET_KEY` تازه بسازید و `DJANGO_DEBUG=False` قرار دهید.
- `DJANGO_ALLOWED_HOSTS` و `DJANGO_CSRF_TRUSTED_ORIGINS` را تنظیم کنید.
- `python manage.py collectstatic` را اجرا و فایل‌های `media/` را روی دیسک پایدار نگه دارید.
- برای ترافیک واقعی، دیتابیس را به PostgreSQL تغییر دهید.
- `SMS_BACKEND` و `PAYMENT_GATEWAY` را از حالت دمو خارج کنید.
